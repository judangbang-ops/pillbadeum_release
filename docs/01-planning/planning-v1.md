# 한 번만 약통 — 기획 초안 (로컬 설계 전달용)

## 0. 이 문서의 용도

이 문서는 구현 지시서가 아니라 설계 입력이다. 아래 MVP 범위를 만들되, "확장 범위"를 처음부터 고려한 데이터 모델과 모듈 구조를 먼저 제안할 것.
설계안을 먼저 보여주고 승인받은 뒤 구현에 들어간다.

첨부: `ui-mockup.html` (홈 화면 위젯 + 앱 내부 화면 시안, 브라우저로 열면 위젯 탭 동작 체험 가능)

## 1. 목적

아침마다 "약 먹었나? 또 먹어도 되나?" 고민하는 문제를 없앤다.
핵심 가치는 이중투약 방지. 복용 기록을 멱등하게 만들어서, 같은 기간에 같은 약은 몇 번을 눌러도 한 번만 기록되게 한다.

## 2. 플랫폼

- Android (갤럭시), Kotlin
- 홈 화면 위젯: Jetpack Glance 권장
- 앱 내부 UI: Jetpack Compose
- 저장: 로컬 DB (Room 등). 서버 없음 (MVP)

## 3. MVP 범위

### 3.1 약 등록 (앱)
- 이름
- 대상자: 나 / 가족 (예: 엄마)
- 주기
  - 매일: 시간대(아침·점심·저녁·자기 전)
  - 주 1회: 기준 요일
- 수정·삭제

### 3.2 홈 화면 위젯
- 등록한 약이 동그라미 버튼으로 나란히 표시 (시안 참고)
- 상태 2가지: 미완료(점선) / 완료(채움 + 체크 + 기록 시각)
- 탭 = 기록. 이미 기록된 기간이면 아무것도 바꾸지 않고 "이미 기록됨, 변경 없음" 안내만
- 위젯에서는 취소 불가

### 3.3 앱 내부 화면
- 오늘·이번 주 기록 목록
- 기록 취소 (앱에서만, 확인 절차 필요)
- 이번 주 요일별 칸 보기

## 4. 멱등성 규칙 (핵심)

- 기록 키 = `기간키 | 약ID`
  - 매일 약: 기간키 = 로컬 날짜 (예: 2026-11-11)
  - 주 1회 약: 기간키 = 주차 (정의는 5.2 결정 필요)
- DB 레벨에서 (약ID, 기간키) 유니크 제약 + insert-or-ignore. 앱 로직 체크만으로 막지 말 것 (위젯·앱 동시 탭 경쟁 상태 대비)
- 기록 성공·무시 여부와 관계없이 위젯은 DB 상태 기준으로 다시 그림
- 시간대: Asia/Seoul 기준, 기기 시간대 변경 시 동작 정의 필요

## 5. 설계 시 결정할 것 (열린 질문)

1. 취소의 의미: 기록 삭제(hard delete) vs 무효 처리(void, 이력 보존). 확장(처방·투약 이력)을 생각하면 이력 보존 쪽을 검토할 것
2. 주 1회 약의 "주" 정의: 달력 주(월~일) vs 마지막 투약일로부터 7일. 예: 월요일 약을 일요일에 늦게 맞았으면 다음 기록은 언제부터 가능한가
3. 매일 약을 자정 직후에 기록하면 어느 날짜로 칠 것인가 (하루 경계 시각 설정 여부)
4. 가족(엄마) 약을 같은 위젯에 둘지, 대상자별 위젯을 따로 둘지

## 6. 확장 범위 (지금 구현 X, 지금 설계엔 반영 O)

### 6.1 처방전 관리
- 처방전: 처방일, 병원, 진료과, 처방 일수, 처방 약 목록
- 약 재고: 처방 수량 대비 남은 양, 소진 예상일
- 재처방·재진 알림

### 6.2 투약 관리
- 복용·투약 이력 전체 조회, 기간별 순응도
- 주사제 관리 (주사 부위 기록·순환 등)
- 진료 때 보여줄 이력 요약·내보내기

### 6.3 기타
- 여러 대상자(가족) 프로필
- 알림 (미복용 시 리마인드)
- 백업·기기 이전

### 6.4 지금 설계에 반영해야 할 것
- 엔티티 분리: 대상자(Person) / 약(Medication) / 복용 일정(Schedule) / 복용 기록(DoseRecord) / 처방전(Prescription, 나중)
- Schedule 일반화: 매일 N회, 주 N회, 격주, N일마다, 필요시(PRN)를 나중에 추가해도 기록 키 규칙이 깨지지 않게
- 약과 처방전 연결 가능한 구조 (지금은 nullable로 비워둬도 됨)
- 기록은 이벤트로 쌓는 구조를 우선 검토 (취소도 이벤트)

## 7. 범위 밖 (하지 않음)

- 복용량 권고, 약물 상호작용 경고 등 의학적 판단. 앱은 기록 도구다
- 서버·계정 (MVP)

## 8. 개인정보

- 복용약·처방 정보는 민감 정보다. 기기 로컬 저장 우선, 백업 기능을 만들 때 암호화와 저장 위치를 별도로 검토

## 9. 검증 요청

설계안과 구현 각각에 대해 isValid(형식) / soundness(정합) / completeness(누락) / 반례 탐색을 하고, 테스트 실행 결과로 증거를 첨부할 것. 최소 반례 목록:

- 같은 약을 위젯에서 빠르게 연속 두 번 탭
- 위젯과 앱에서 거의 동시에 기록
- 23:59에 탭, 00:00 넘어서 다시 탭
- 주 경계(일요일 밤 → 월요일) 전후 주 1회 약 기록
- 기록 취소 후 같은 기간에 다시 기록
- 기기 시간대·시각 수동 변경
- 약 삭제 후 해당 약의 기존 기록 처리
- 주기 변경(매일 → 주 1회) 시 기존 기록 처리
