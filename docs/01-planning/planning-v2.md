# DidITake (한 번만 약통) — 기획 초안 v2 (로컬 설계 전달용)

## 0. 이 문서의 용도

이 문서는 구현 지시서가 아니라 설계 입력이다. MVP를 만들되, 6장 "확장 범위"를 처음부터 고려한 데이터 모델과 모듈 구조를 먼저 제안할 것.
설계안을 먼저 보여주고 승인받은 뒤 구현에 들어간다.

- 앱 표시 이름: DidITake
- 작업 폴더: did-i-take (패키지명은 소문자 diditake 기준)
- 첨부: `ui-mockup.html` (홈 화면 위젯 + 앱 내부 화면 시안, 브라우저로 열면 위젯 탭 동작 체험 가능)

## 1. 목적

아침마다 "약 먹었나? 또 먹어도 되나?" 고민하는 문제를 없앤다.
핵심 가치는 이중투약 방지. 복용 기록을 멱등하게 만들어서, 같은 기간에 같은 약은 몇 번을 눌러도 한 번만 기록되게 한다.
장기적으로는 처방·투약·복용일기를 한곳에서 관리하고, 진료 때 의사에게 보여줄 기간별 요약을 만드는 것까지 간다.

## 2. 플랫폼

- Android (갤럭시), Kotlin
- 홈 화면 위젯: Jetpack Glance 권장
- 앱 내부 UI: Jetpack Compose
- 저장: 로컬 DB (Room 등). 서버 없음
- AI 기능 없음 (복용일기 요약 포함, 7장 참고)

## 3. MVP 범위

### 3.1 약 등록 (앱)
- 이름
- 대상자: 나 / 가족 (예: 엄마)
- 주기
  - 매일: 시간대(아침·점심·저녁·자기 전)
  - 주 1회: 기준 요일
- 수정·삭제

### 3.2 홈 화면 위젯
- 등록한 약이 동그라미 버튼으로 나란히 표시 (시안 참고)
- 상태 2가지: 미완료(점선) / 완료(채움 + 체크 + 기록 시각)
- 탭 = 기록. 이미 기록된 기간이면 아무것도 바꾸지 않고 "이미 기록됨, 변경 없음" 안내만
- 위젯에서는 취소 불가

### 3.3 앱 내부 화면
- 오늘·이번 주 기록 목록
- 기록 취소 (앱에서만, 확인 절차 필요)
- 이번 주 요일별 칸 보기

## 4. 멱등성 규칙 (핵심)

- 기록 키 = `기간키 | 약ID`
  - 매일 약: 기간키 = 로컬 날짜 (예: 2026-11-11)
  - 주 1회 약: 기간키 = 주기 회차 (정의는 5장 결정 필요)
- DB 레벨에서 (약ID, 기간키) 유니크 제약 + insert-or-ignore. 앱 로직 체크만으로 막지 말 것 (위젯·앱 동시 탭 경쟁 상태 대비)
- 기록 성공·무시 여부와 관계없이 위젯은 DB 상태 기준으로 다시 그림
- 시간대: Asia/Seoul 기준, 기기 시간대 변경 시 동작 정의 필요

## 5. 설계 시 결정할 것 (열린 질문)

1. 취소의 의미: 기록 삭제 vs 무효 처리(이력 보존). 확장을 생각하면 이력 보존 쪽을 검토할 것
2. 주 1회 약의 "주" 정의: 약별로 "고정 요일" 방식과 "마지막 투약일 기준" 방식 중 선택 가능하게 할지. 6.2 주기 밀림과 함께 결정
3. 매일 약을 자정 직후에 기록하면 어느 날짜로 칠 것인가 (하루 경계 시각 설정 여부)
4. 가족(엄마) 약을 같은 위젯에 둘지, 대상자별 위젯을 따로 둘지

## 6. 확장 범위 (지금 구현 X, 지금 설계엔 반영 O)

### 6.1 미복용·건너뜀
- 매일 약을 빼먹은 경우: 기록 없음 = 미복용으로 표시
- "깜빡함"과 "일부러 건너뜀"(의사 지시 등)을 구분할 수 있게 건너뜀 기록을 별도 이벤트로 둔다
- 빼먹었을 때 어떻게 하라는 안내(다음에 두 배 등)는 하지 않는다. 기록만 한다

### 6.2 주기 밀림 (주 1회 약·주사)
- 예정일에 못 하고 다음 날이나 며칠 뒤에 한 경우
- 늦게 기록하면 "다음부터 기준일을 오늘로 옮길까요?"를 사용자가 선택
- 옮기면 일정(Schedule)이 새 버전으로 바뀌고, 이전 기록은 이전 버전 기준으로 남는다

### 6.3 반복 패턴 리포트
- 미복용·밀림이 반복될 때 기간별 복용률, 자주 빠지는 요일·시간대 표시
- 탓하는 문구 없이 사실과 제안만 (예: "주말에 자주 빠져요. 알림 시간을 바꿔볼까요?")

### 6.4 용량 변경
- 용량을 덮어쓰지 않는다. "적용 시작일 + 용량" 버전으로 쌓는다
- 과거 기록은 그 시점의 용량으로 보여야 한다
- 진료 요약에 용량 변경 이력이 날짜와 함께 나와야 한다

### 6.5 처방전 관리
- 처방전: 처방일, 병원, 진료과, 처방 일수, 처방 약 목록
- 처방전 사진 첨부
  - 기기 내 문자 인식(예: ML Kit)으로 약 이름·용량·일수를 미리 채움
  - 반드시 사용자가 확인·수정한 뒤 저장 (인식 오류가 그대로 들어가지 않게)
  - 사진·인식 처리는 외부 서버로 보내지 않음
- 약 재고: 처방 수량 대비 남은 양, 소진 예상일
- 재처방·재진 알림

### 6.6 복용일기 + 진료 전 요약 (AI 사용 안 함)
- 입력 두 가지
  - 고정형: 약별로 설정하는 항목. 예: 컨디션 0~10, 부작용 체크리스트(약마다 다르게 설정), 주사 부위 등
  - 짧은 메모: 폰으로 짧게 쓰는 자유 서술. 저장 시 날짜·시간 자동 기록
- 진료 전 요약
  - 사용자가 기간을 지정 (예: 지난 진료일 ~ 오늘)
  - 구성: 기간 복용률, 용량 변경 이력, 고정형 항목 추이(예: 컨디션 평균·변화), 부작용 체크된 날 목록, 메모 원문
  - 메모는 요약·가공하지 않고 날짜·시간 순으로 단순 병합해서 정갈하게 표시
  - 진료실에서 화면을 바로 보여줄 수 있는 레이아웃 + 내보내기(PDF 등) 검토

### 6.7 약 정보 보기
- 1순위(간단·안전): 약 상세에 health.kr 등 약 정보 페이지 링크 버튼 → 앱 내 브라우저(Custom Tabs)로 열기
- 외부 사이트 내용을 긁어와서 앱 화면에 재가공해 보여주는 것은 하지 않음 (이용약관·저작권)
- 2순위(검토): 공공데이터포털 식약처 오픈API
  - e약은요: 환자용 복약정보. 단, 일반의약품만 있고 전문의약품은 없음
  - 의약품 제품 허가정보: 전문의약품 포함
  - 낱알식별: 알약 모양·색·각인·이미지
  - 현재 정상 제공 여부와 이용 조건을 붙이기 전에 확인할 것

### 6.8 다른 병원 약 병용 확인
- 앱이 "충돌 여부"를 판정하지 않는다
- 기본 기능: 대상자별 "현재 복용 중인 전체 약 목록(병원별)" 화면. 새 병원·약국에서 보여주기용
- 선택 기능(검토): 식약처 DUR 품목정보 오픈API의 병용금기 데이터와 대조
  - 등록된 조합이 있을 때만 "DUR 병용금기로 등록된 조합입니다. 약사·의사에게 확인하세요" 경고 표시
  - 경고가 없을 때 "충돌 없음", "안전" 같은 문구는 절대 표시하지 않음 (DUR에 없다고 안전하다는 뜻이 아님)

### 6.9 기타
- 여러 대상자(가족) 프로필
- 알림 (미복용 리마인드)
- 백업·기기 이전

### 6.10 사용자 신체·질병 정보 (키·몸무게·성별·혈액형·질병)
- MVP와 초기 확장에서는 받지 않음. 앱이 복용량 계산 등 의학적 판단을 하지 않으므로 쓸 데가 없음
- 나중에 "진료용 내 정보 카드"가 생기면 선택 입력 + 기기 내 암호화 저장으로 검토

### 6.11 지금 설계에 반영해야 할 것
- 엔티티 분리
  - Person (대상자)
  - Medication (약)
  - DoseVersion (용량 버전: 적용 시작일, 용량)
  - ScheduleVersion (일정 버전: 주기 유형, 기준일, 적용 시작일)
  - DoseRecord (복용 기록 이벤트: 기록 / 건너뜀 / 취소)
  - DiaryEntry (복용일기: 고정형 값 + 메모 + 작성 시각)
  - Prescription, PrescriptionItem, Attachment (나중)
- Schedule 일반화: 매일 N회, 주 N회, 격주, N일마다, 필요시(PRN)를 나중에 추가해도 기록 키 규칙이 깨지지 않게
- 약과 처방전 연결 가능한 구조 (지금은 nullable로 비워둬도 됨)
- 기록은 이벤트로 쌓는 구조 우선 검토 (취소·건너뜀도 이벤트)
- "언제부터 적용"이 있는 값(용량·일정)은 덮어쓰기 금지, 버전으로 관리

## 7. 범위 밖 (하지 않음)

- 복용량 권고, 빼먹었을 때 처치 안내, 약물 상호작용 "판정" 등 의학적 판단. 앱은 기록·표시 도구다
- AI 요약·생성 기능 (복용일기 포함)
- 외부 약 정보 사이트 스크래핑
- 서버·계정

## 8. 개인정보

- 복용약·처방·복용일기·처방전 사진은 민감 정보다. 기기 로컬 저장 우선
- 백업 기능을 만들 때 암호화와 저장 위치를 별도로 검토
- 신체·질병 정보는 받지 않는 것이 기본 (6.10)

## 9. 검증 요청

설계안과 구현 각각에 대해 isValid(형식) / soundness(정합) / completeness(누락) / 반례 탐색을 하고, 테스트 실행 결과로 증거를 첨부할 것. 최소 반례 목록:

- 같은 약을 위젯에서 빠르게 연속 두 번 탭
- 위젯과 앱에서 거의 동시에 기록
- 23:59에 탭, 00:00 넘어서 다시 탭
- 주 경계 전후 주 1회 약 기록
- 주 1회 약을 이틀 늦게 기록하고 기준일을 옮긴 경우 / 안 옮긴 경우 다음 회차 계산
- 기록 취소 후 같은 기간에 다시 기록
- 건너뜀 기록 후 같은 기간에 복용 기록
- 기기 시간대·시각 수동 변경
- 약 삭제 후 해당 약의 기존 기록 처리
- 주기 변경(매일 → 주 1회) 시 기존 기록 처리
- 기간 중간에 용량이 바뀐 경우 진료 요약의 용량·복용률 표시
- 복용일기 메모를 같은 분에 여러 개 쓴 경우 병합 순서
