## 1. 목적

아침마다 "약 먹었나? 또 먹어도 되나?" 고민하는 문제를 없앰. 핵심 가치는 이중투약 방지임. 같은 창에 같은 복용 항목은 몇 번을 눌러도 한 번만 기록되게 함.

장기적으로는 처방·투약·복용일기를 한곳에서 관리하고, 진료 때 의사에게 보여줄 기간별 요약을 만드는 것까지 감.

## 2. 플랫폼

- 1단계: Android(갤럭시). APK 직접 설치. 스토어 배포는 하지 않음
- 2단계: iOS(아이폰). 같은 코드베이스로 확장
- 그다음: 백엔드. 동시 처리가 필요함
- MVP는 서버·계정 없이 기기 로컬에서 돎. 대신 백엔드로 옮기기 쉽게 메타데이터를 설계함 (2.3)
- AI 기능 없음

### 2.1 크로스플랫폼 원칙

확정된 기술 스택은 [architecture](../02-design/architecture.md#2-기술-스택-확정)에 있음. 아래는 스택과 관계없이 지금 정해 두는 원칙임.

1. 모든 쓰기(위젯·앱·알림 버튼)는 공통 기록 함수 하나를 거침
2. 멱등 보장은 DB 유니크 제약이 맡음. iOS 위젯은 앱과 별도 프로세스라 앱 안의 잠금으로는 막을 수 없음
3. 시간 계산은 공통 코드에서 돌아가는 라이브러리(kotlinx-datetime 등)로 함
4. SQLite는 앱에 함께 넣은 드라이버를 씀. 플랫폼별 SQLite 버전 차이를 없앰
5. 알림은 "미리 예약하고, 기록되면 취소"하는 방식으로 함. iOS는 정해진 시각에 앱 코드를 실행할 수 없음
6. 백업·기기 이전 파일 형식은 플랫폼 중립으로 함. 갤럭시에서 아이폰으로 옮기는 유일한 방법임
7. iOS 최소 버전은 17임. 위젯 버튼으로 바로 기록할 수 있는 첫 버전임

### 2.2 APK 운영 규칙 (1단계)

- 서명 키를 처음부터 하나로 고정하고 저장소 밖에 백업함. 키가 바뀌면 업데이트가 안 되고, 지우고 다시 설치하면 기기에 저장된 기록이 모두 사라짐
- 여러 PC에서 빌드할 때도 같은 키를 씀. PC마다 디버그 키가 달라 같은 문제가 생김
- 서명 키와 비밀번호는 커밋하지 않음

### 2.3 추후 백엔드 대비

과하게 만들지 않음. MVP에는 서버·로그인·동기화를 넣지 않고, 아래 메타데이터만 처음부터 맞춤. 상세는 [data-model](../02-design/data-model.md#0-공통-메타데이터)에 있음.

- 모든 행의 ID는 기기에서 만드는 UUIDv7임. 자동 증가 정수를 쓰지 않음
- 모든 행에 만든 시각·고친 시각·버전·만든 기기를 둠
- 지우지 않고 보관 처리함. 동기화 때 삭제 표시로 씀
- 상태 값은 고정 문자열 코드로 저장함
- 창·판정 규칙은 서버에서도 같은 코드로 돌 수 있게 플랫폼 API 없이 작성함
- 활성 판정 1개를 보장하는 유니크 구조는 서버 DB(PostgreSQL)에서도 그대로 통함

## 3. MVP 범위 (1단계)

### 3.1 복용 항목 등록 (앱)

- 이름, 대상자(나/가족), 주기
  - 매일: 하루 1회. 시간대 표시(아침·점심·저녁·자기 전)
  - 주 1회: 기준 요일
- MVP에서는 항목 1개가 하루 1회 또는 주 1회임. 아침·저녁 두 번 먹는 약은 항목 2개로 등록함
- 수정은 일정의 새 버전으로 저장함. 덮어쓰지 않음
- 삭제는 보관 처리함. 기록은 남음. 완전 삭제는 앱에서 별도 확인을 거침
- 위젯 표시 이름(별칭)을 선택해서 넣을 수 있음. 홈 화면에 약 이름이 그대로 보이는 것을 피하는 용도임
- 복용 항목과 약의 연결 구조는 스키마에 두되, MVP 화면에는 드러내지 않음

### 3.2 홈 화면 위젯

- 등록한 항목이 동그라미 버튼으로 나란히 표시됨
- 상태: 미완료(점선) / 완료(채움 + 체크 + 기록 시각)
- 머리글에 기준 날짜를 표시함 (예: `11/11 (수)`). 갱신이 늦은 위젯을 눈으로 알아보게 함
- 미완료 칸 보조 문구는 마지막 기록 시각임 (예: `마지막 어제 22:00`)
- 미완료 아이콘은 빈 원임. `+`는 "약 추가"로 읽힐 수 있어 쓰지 않음
- 위젯마다 대상자 필터(나/가족/전체)를 둠. 사람별 색·이니셜을 표시함
- **위젯 원칙: 비어 있는 창에만 판정을 만듦. 이미 있는 판정(기록·건너뜀)은 앱에서만 바꿈**
- 탭 = 기록. 이미 판정이 있으면 바꾸지 않고 "이미 기록됨 (08:02)"만 안내함
- 탭할 때 위젯이 그려진 시점의 기간키를 함께 보냄. 지금 기간키와 다르면 기록하지 않고 새로고침한 뒤 "날짜가 바뀌었어요. 다시 눌러 주세요"를 안내함
- 보관된 항목의 버튼이 남아 있으면 기록하지 않고 새로고침함
- 위젯에서는 취소할 수 없음

### 3.3 앱 화면

- 오늘·이번 주 기록 목록
- 기록 취소: 앱에서만, 확인 절차를 거쳐 무효 처리함
- 이번 주 요일별 칸 보기
- 늦은 입력: 실제 복용 시각을 고칠 수 있음. 입력 시각은 따로 남김
- 설정: 하루 시작 시각(기본 04:00), 기준 시간대(기본 Asia/Seoul), 백업 정책

## 4. 기록 규칙 (멱등)

상세 규칙과 반례별 기대 동작은 [record-rules](../02-design/record-rules.md)에 있음. 요약은 다음과 같음.

- 창: 매일 약은 [D 04:00, D+1 04:00), 주 1회 약은 기준 요일 04:00부터 7일
- 기간키: 창 시작 날짜(절대값). 상대 회차 번호와 ISO 주번호는 쓰지 않음. 기준일을 옮기거나 연말연초를 지날 때 키가 겹치거나 갈라짐
- 판정 저장: 기록 행에 `active`(1 또는 NULL)를 두고 `(항목, 기간키, active)` 유니크 제약을 걺. 무효 처리된 행은 여러 개 남고, 활성 판정은 1개만 허용됨
- 판정 계산: 기간키가 지금 창과 같거나, 실제 복용 시각이 지금 창 안에 있는 활성 판정이 있는지 봄. 주기·기준일·하루 시작 시각이 바뀌어도 맞게 판정함
- 쓰기: 공통 기록 함수가 쓰기 트랜잭션 안에서 판정 확인과 삽입을 함께 함. 유니크 제약은 연타·동시 탭에 대비한 마지막 보장임
- 시간대: 기준 시간대(설정, 기본 Asia/Seoul)로 창을 계산함. 기기 시간대가 바뀌어도 창은 그대로임

## 5. 확정된 결정 (v2 열린 질문, 2026-11-11)

1. **취소 = 무효 처리(이력 보존).** 기록 행을 지우지 않음
2. **주 1회의 "주" = 기준 요일 창 하나.** 두 방식을 고르는 기능은 두지 않음
   - 달력 주(월~일)는 금요일 약이 월요일부터 미완료로 보여 일찍 맞도록 유도함
   - "마지막 투약일 기준"은 "늦을 때마다 기준일을 옮김"과 같은 동작임
   - 늦게 맞은 경우의 처리는 약별 설정임: 매번 묻기(기본) / 항상 기준일 옮기기 / 항상 유지
   - 일찍 맞은 경우는 앱에서 "다음 회차 몫으로 기록 + 기준일 옮기기"로 처리함
3. **하루 경계 = 설정값(하루 시작 시각), 기본 04:00.** 경계는 옮겨질 뿐 없어지지 않으므로 위젯에 마지막 기록 시각을 함께 표시함
4. **가족 = 위젯 1종 + 위젯마다 대상자 필터**

## 6. 확장 범위 (지금 구현하지 않음, 설계에는 반영함)

### 6.1 미복용·건너뜀

- 빠짐 = 끝난 창에 판정이 없는 상태 (계산값, 저장하지 않음)
- 빠짐 계산에서 제외: 일정 시작 전, 중단 구간, 보관된 항목
- "깜빡함"과 "일부러 건너뜀(의사 지시 등)"을 구분하려고 건너뜀을 판정의 한 종류로 둠
- 오래 중단하는 경우(예: 수술 전 2주)는 건너뜀을 반복 기록하지 않고 일정 버전에 중단 구간을 둠
- 건너뜀 칸도 위젯에서 바꾸지 않음. 앱에서 "건너뜀 → 복용"으로 바꾸면 건너뜀을 무효 처리하고 복용을 새로 기록함
- 빼먹었을 때 어떻게 하라는 안내는 하지 않음. 기록만 함

### 6.2 주기 밀림 (주 1회 약·주사)

- 예정일에 못 하고 다음 날이나 며칠 뒤에 한 경우임
- 늦게 기록하면 약별 설정(5장 2번)에 따라 기준일을 옮김. 위젯에서 기록한 경우 질문은 앱이나 알림으로 함
- 옮기면 일정이 새 버전이 되고, 이전 기록은 이전 버전 기준으로 남음

### 6.3 반복 패턴 리포트

- 복용률은 숫자 하나로 합치지 않고 나눠서 보여줌. 예: "복용 26 / 예정 28 (건너뜀 1 · 빠짐 1)"
- 자주 빠지는 요일·시간대를 보여줌. 기간이 짧아 표본이 적으면 패턴 문구를 띄우지 않음
- 탓하는 문구 없이 사실과 제안만 씀 (예: "주말에 자주 빠져요. 알림 시간을 바꿔볼까요?")

### 6.4 용량 변경

- 용량은 약 단위로 "적용 시작일 + 용량" 버전을 쌓음. 덮어쓰지 않음
- 기록 행에 용량을 복사하지 않고, 복용 시각에 맞는 버전을 조회해서 보여줌. 진료 뒤 "지난주부터 바뀌었어"처럼 늦게 입력하는 경우에 대응함
- 진료 요약에 용량 변경 이력을 날짜와 함께 보여줌

### 6.5 처방전 관리

- 처방전: 처방일, 병원, 진료과, 처방 일수, 처방 약 목록, 사진 첨부
- 기기 안 문자 인식으로 약 이름·용량·일수를 미리 채우고, 사용자가 확인·수정한 뒤 저장함. 사진·인식 처리는 외부로 보내지 않음
- 처방전에 약품 보험코드가 함께 찍혀 있으면 이름보다 코드가 공공 의약품 데이터와 맞추기 쉬움 (실물 처방전으로 확인 필요)
- 약 재고(남은 양·소진 예상일), 재처방·재진 알림
- 약국 봉투(아침약 등)의 구성은 그 시점에 유효한 처방의 시간대별 약으로 계산할 수 있음

### 6.6 복용일기 + 진료 전 요약 (AI 사용 안 함)

- 고정형 항목(컨디션 0~10, 약별 부작용 체크리스트)과 짧은 메모를 입력함
- 일기는 "무슨 날의 일인가(`occurred_on`)"와 "언제 썼나(`written_at`)"를 따로 저장함. 새벽에 "어제 저녁 두통"을 쓰는 경우에 대응함
- 같은 분에 쓴 메모 여러 개는 (`written_at` 밀리초, id) 순으로 정렬함
- 고정형 항목 정의는 지우지 않고 보관 처리함. 항목을 빼도 옛 일기는 그대로 보여야 함
- 주사 부위는 일기가 아니라 투약 기록의 속성으로 둠. 회차마다 1개이며, 부위 순환도 기록을 기준으로 계산함
- 진료일(Visit)을 따로 저장함. "지난 진료일 ~ 오늘" 요약의 기준점임
- 요약 구성: 기간 복용률(분해), 용량 변경 이력, 고정형 항목 추이, 부작용이 체크된 날, 메모 원문(가공 없이 시간순)
- 진료실에서 바로 보여줄 화면 + PDF 내보내기

### 6.7 약 정보 보기

- 1순위: 약 정보 페이지 링크를 앱 내 브라우저로 엶. 외부 사이트 내용을 긁어 오지 않음
- 2순위(검토): 공공데이터포털 식약처 오픈API. e약은요는 일반의약품만 있고, 제품 허가정보는 전문의약품을 포함하며, 낱알식별은 알약 모양·색·각인을 제공함. 붙이기 전에 제공 상태와 이용 조건을 확인함
- 조회하면 복용 약 이름이 외부로 나감. 사용자가 버튼을 누를 때만 조회하고 결과는 기기에 저장해 둠

### 6.8 다른 병원 약 병용 확인

- 앱이 충돌 여부를 판정하지 않음
- 기본 기능: 대상자별 현재 복용 중인 전체 약 목록(병원별) 화면. 새 병원·약국에서 보여주는 용도임
- 처방약끼리는 처방·조제 단계에서 이미 DUR 점검을 받음. 앱 대조의 빈틈은 일반약·영양제 쪽이 큼. 그래서 목록 화면을 먼저 만들고 DUR 오픈API 대조는 뒤로 미룸
- 대조하더라도 등록된 조합에만 경고하며, 경고가 없을 때 "충돌 없음", "안전" 같은 문구는 쓰지 않음

### 6.9 기타

- 여러 대상자(가족) 프로필
- 백업·기기 이전: 플랫폼 중립 파일
- MVP에는 서버가 없으므로 기기 두 대 사이(예: 가족이 각자 폰으로 같은 약을 기록)의 이중투약은 막을 수 없음. "한 약은 한 기기가 기록을 맡음" 원칙을 안내함. 백엔드가 붙으면 동기화 때 감지해 안내함

### 6.10 신체·질병 정보

- MVP와 초기 확장에서는 받지 않음. 앱이 의학적 판단을 하지 않으므로 쓸 곳이 없음
- 나중에 "진료용 내 정보 카드"를 만들면 선택 입력 + 기기 내 암호화 저장으로 검토함

### 6.11 지금 설계에 반영할 것

**(A) MVP 스키마부터 맞아야 하는 것** — 나중에 바꾸면 쌓인 데이터를 옮겨야 함

- 기간키 규칙, `active` 유니크 구조, 실제 복용 시각과 입력 시각 분리, 시간대 저장, 보관 처리, 일정 버전
- 엔티티: Person, Intake(복용 항목), Medication(약), IntakeMedication(구성), ScheduleVersion, DoseVersion, DoseRecord, Setting

**(B) 나중에 테이블을 추가하면 되는 것**

- Visit, Prescription, PrescriptionItem, Attachment, DiaryEntry, DiaryFieldDef, DiaryValue, DoseDetail(주사 부위), ReminderRule

상세는 [data-model](../02-design/data-model.md)에 있음.

### 6.12 반복 알림 (신규)

- 요구: 정한 시간에 복용 기록이 없으면, 사용자가 정한 간격(예: 1시간)마다 "아침약 먹어~!"를 반복해서 알림
- 방식: 앱 자체 알림(기기 로컬 알림)으로 확정함 (2026-11-11). 서버·외부 메신저가 필요 없고 인터넷 없이 동작함
- 동작
  - 알림 시작 시각에 1회, 이후 간격마다 반복함
  - 기록·건너뜀이 되면 남은 알림을 바로 취소함. 기록을 취소(무효 처리)했는데 창이 아직 열려 있으면 다시 예약함
  - 창이 끝나거나, 방해 금지 시간이거나, 하루 최대 횟수에 닿으면 멈춤
- 알림 버튼: [먹었어] (공통 기록 함수로 바로 기록, 기간키 대조 포함) / [30분 뒤] / [오늘 건너뜀]
- 알림·잠금 화면에 약 이름을 보일지 설정함
- Android: 정확한 시각에 울리려면 정확 알람 권한이 필요함. Android 14부터 기본으로 주어지지 않아 사용자 허용을 받거나 배터리 최적화 예외 앱으로 등록해야 함(예외 앱은 정확 알람을 쓸 수 있음). 갤럭시 절전 예외 안내와 함께 처리함. Android 13부터는 알림 권한도 요청함
- iOS: 미리 예약해야 하며 대기 알림이 64개로 제한됨. 가까운 알림만 예약하고 기록·앱 실행 때 보충함
- 카카오톡: 추후 확장 기능으로 보류함 (2026-11-11). 조사 결과는 다음과 같음
  - '나에게 보내기'는 메모 용도라 알림이 울리지 않음 (카카오 데브톡 공식 답변 기준, 실기기 확인 권장)
  - '친구에게 보내기'는 비즈 앱 전환·심사가 필요하고, 같은 발신자→수신자 하루 20건 제한이 있음
  - 알림톡은 사업자·채널·템플릿 심사·유료·서버가 필요함
  - 위 이유로 반복 알림 채널로는 맞지 않음

## 7. 범위 밖 (하지 않음)

- 복용량 권고, 빼먹었을 때 처치 안내, 약물 상호작용 판정 등 의학적 판단. 앱은 기록·표시 도구임
- AI 요약·생성 기능 (복용일기 포함)
- 외부 약 정보 사이트 스크래핑
- 서버·계정 (MVP 한정. 백엔드는 다음 단계에서 붙임)
- 카카오톡 알림 (추후 확장으로 보류)

## 8. 개인정보

- 복용약·처방·복용일기·처방전 사진은 민감 정보임. 기기 로컬 저장을 우선함
- Android 자동 백업은 기본으로 켜져 있어 그대로 두면 DB가 구글 드라이브로 올라감. MVP에서 백업 허용 여부와 범위를 명시적으로 정함
- 홈 화면 위젯·알림·잠금 화면에 약 이름이 보임. 별칭과 표시 여부 설정을 둠
- 외부 API 조회는 사용자가 누를 때만 함
- 외부 메신저와 연동한다면 보내는 문구에 약 이름을 넣지 않음
- 신체·질병 정보는 받지 않는 것이 기본임 (6.10)
- 저장소에는 실제 복용 기록·가족 건강정보를 올리지 않음. 문서 예시는 가상의 이름을 씀

## 9. 검증 요청

설계안과 구현 각각에 대해 형식(isValid)·정합(soundness)·누락(completeness)·반례 탐색을 하고, 테스트 실행 결과로 증거를 첨부함. 반례별 기대 동작은 [record-rules](../02-design/record-rules.md#9-반례별-기대-동작)에 표로 정리함.

v2 반례:

1. 같은 항목을 위젯에서 빠르게 연속 두 번 탭
2. 위젯과 앱에서 거의 동시에 기록
3. 23:59에 탭, 00:00 넘어서 다시 탭
4. 주 경계 전후 주 1회 약 기록
5. 주 1회 약을 이틀 늦게 기록하고 기준일을 옮긴 경우 / 안 옮긴 경우 다음 회차 계산
6. 기록 취소 후 같은 기간에 다시 기록
7. 건너뜀 기록 후 같은 기간에 복용 기록
8. 기기 시간대·시각 수동 변경
9. 약 삭제 후 해당 약의 기존 기록 처리
10. 주기 변경(매일 → 주 1회) 시 기존 기록 처리
11. 기간 중간에 용량이 바뀐 경우 진료 요약의 용량·복용률 표시
12. 복용일기 메모를 같은 분에 여러 개 쓴 경우 병합 순서

v3 추가 반례:

13. 날짜가 바뀐 뒤 갱신되지 않은 위젯의 완료 칸을 탭
14. 항목 보관 직후, 갱신되지 않은 위젯 버튼을 탭
15. 하루 시작 시각 설정을 새벽에 바꿈
16. 기준 요일을 바꾼 당일
17. 주 1회 약을 이틀 일찍 맞음
18. 재부팅 후 경계 시각 알람과 반복 알림 다시 예약
19. 시계를 미래로 돌렸다 되돌림 (미래 시각 기록)
20. 연말연초 (2026년은 ISO 기준 53주가 있는 해)
21. 반복 알림 중에 위젯으로 기록 → 남은 알림 취소
22. 기록 취소 후 창이 아직 열려 있음 → 알림 다시 예약
23. 날짜가 바뀐 뒤 알림의 [먹었어]를 누름
