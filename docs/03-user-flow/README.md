# 사용자 흐름 (CORTHEX 03)

- 상태: **초안, 확인 전** (2026-11-12, Claude). 02 요구 다시 하기(범위 확인 기다림)를 입력으로 씀
- 입력: [요구사항](../01-planning/requirements.md) REQ-001~093, [도메인 설계](../01-domain/domain.md)의 경계 CTX-001~005와 용어집 TERM-001~031, [화면 목록](../05-ui/sitemap.yaml)의 SCR ID
- 시안: 가쟈누님 DidITake [플로우 초안](https://github.com/judangbang-ops/DidITake/blob/7a800ac/docs/04-flow/flows.md)은 참고만 함. 그 초안의 위젯 탭 판단(3장)과 반복 알림(4장)은 FL-002·003에 들어왔고, 그 초안에 없던 지난 기록 보기(FL-005)와 복원(FL-009)을 더함

## 읽는 법

- 흐름 하나는 챙기는 사람이 앱에 오는 목적 하나임. 파일마다 Mermaid 그림이 하나 있고 GitHub에서 그림으로 보임
- 칸 아래 줄의 `REQ-…`는 그 칸이 맡는 요구, `SCR-…`는 그 칸의 화면(`#…`는 [화면 문서](../05-ui/screens.md)의 화면별 상태)
- `([ ])`는 시작과 끝, `{ }`는 갈림길, `[ ]`는 한 동작. 갈림길은 모든 갈래를 그림
- 파일 머리의 '쓰는 요구'는 그림에 나온 요구와 같아야 함 (스크립트가 봄)

## 흐름 밖

아래 요구는 한 흐름의 칸이 아니라 앱 전체에 걸린 제약이나 출시 작업이라 흐름에 그리지 않음. 각각 합격 기준대로 코드 검사, 기기 시험, 출시 점검으로 확인함(요구 문서의 합격 기준 열, [작업 분해](../08-wbs/wbs.md)).

| 의료 문구 제한 | REQ-087, REQ-048 | 하지 않는 일(복용 권고, 알림 시간 약속)이라 칸이 없음. 문구 검사로 봄 |

## 검사 (스크립트)

[`.github/scripts/check_docs.py`](../../.github/scripts/check_docs.py)가 PR마다 봄.

- 파일 이름과 제목의 FL ID가 같고, 파일마다 Mermaid 그림이 하나임
- 머리의 '쓰는 요구'와 그림의 요구가 같고, 모르는 REQ·SCR ID가 없음. 화면별 상태(`SCR-…#…`)는 화면 문서에 있어야 함
- 갈림길마다 갈래가 둘 이상이고, 끝이 아닌 칸은 모두 다음 칸으로 이어지며, 흐름마다 끝이 있음
- 기능 요구는 모두 흐름 하나 이상에 있음. 흐름에 없는 요구는 모두 위 '흐름 밖'에 있음

3. FL-009: 복원 안내를 확인하기 전에는 복용 알림을 울리지 않음
