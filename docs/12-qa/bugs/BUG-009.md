대상: TC-093, SPEC-003, SPEC-048, SCR-006, REQ-001.

현상: CI의 연속 저장 시험에서 기존 항목 하나에 추가한 뒤 기대 2건 대신 3건이었다. CI 원본 XML은 실행 46107828577의 app-render 아티팩트에 있다. 2026-11-28 Linux Robolectric API 35에서 `19dba36`의 원래 시험은 20/20, 전체 앱 시험은 211/211 통과했다.

재현: 기존 항목을 넣고 항목 추가 화면에서 이름과 약을 적어 저장한다. 새 항목이 화면에 나타나 첫 작업이 완료된 뒤 기존 화면에서 보관한 저장 콜백을 다시 호출하면 `stale_save_callback_after_navigation_does_not_create_a_second_item`은 기대 2건 대신 3건으로 실패한다. 이것은 CI 실패와 결과가 같으며 CI에서 정확히 같은 순서였는지는 증명하지 않는다.

원인: 쓰기 진행 중의 busy만 막고 성공 뒤 화면을 떠난 이전 콜백을 막지 않았다. 수정은 활성 화면 인스턴스가 아니거나 저장 완료 안내 중인 콜백을 거부한다. 승인된 SPEC의 변경은 필요 없다.

회귀: 수정 전 `19dba36`에서 위 회귀 시험이 실패했으며 수정 후 같은 시험을 포함한 ItemMedicationScreenTest를 확인한다. 상태는 수정 PR이 병합되기 전까지 open이다.
