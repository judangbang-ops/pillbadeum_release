대상: SCR-007#loading, REQ-001, SPEC-016~SPEC-019, TC-019·TC-084. 화면 정의는 처리 중 버튼이 눌리지 않아야 한다고 이미 정한다. 명세 변경 없이 구현을 고친다.

## 확인과 재현

[CI 46136548347](https://github.com/judangbang-ops/pillbadeum_release/actions/runs/46136548347)에서 `JudgeScreenTest.a_past_window_records_a_picked_time_and_turns_a_skip_into_a_dose`가 Compose 대화상자를 생성하면서 `DefaultDispatcher` 작업 스레드에 Looper가 없다는 오류로 실패했다. 스택은 앱 일반 실행의 재구성기가 아닌 `AndroidComposeUiTestEnvironment.withWindowRecomposer`와 시험용 `TestMonotonicFrameClock`을 거친다. 실제 앱의 `MainActivity.setContent`는 일반 Android 창 재구성기를 쓰고 화면 동작은 `rememberCoroutineScope`에서 시작하며, 검색한 앱 코드에 작업 스레드에서 별도 Compose 창 재구성기를 만들거나 Dialog를 직접 띄우는 경로는 없었다. 이는 조사한 코드와 스택에 근거한 판정이며 모든 기기에서 문제가 없다는 증명은 아니다.

시험에서 사용하던 Compose 1.11.2 기존 `createEmptyComposeRule`은 `UnconfinedTestDispatcher`를 사용한다. [Android 공식 Compose 시험 문서](https://developer.android.com/develop/ui/compose/testing/migrate-v2)는 기존 방식의 즉시 실행과 v2의 큐 방식 차이를 설명한다. 비제한 시험 디스패처에서 재구성이 작업 스레드로 이어졌을 가능성이 있으나 CI의 정확한 스케줄은 기록돼 있지 않아 단정하지 않는다. 원래 시험을 main `98eb92b`, Linux·Temurin 17·Robolectric API 35에서 독립 실행 20회 반복했을 때 20/20 성공해 그 CI 실패 자체를 로컬에서 재현하지 못했다.

시험 규칙을 v2의 큐 방식으로 바꾸고 같은 흐름을 돌리자, 시각을 전날로 옮긴 결과가 보인 뒤 [기록 취소]의 확인을 눌러도 기록이 무효화되지 않았다. 일시 진단 로그는 `write`의 `busy` 가드가 그 입력을 거절했음을 보였고 DB 행도 활성 상태였다. 판정 화면은 `busy`를 몰라 버튼과 확인을 활성으로 표시한다. 실제 기기에서도 앞 작업의 위젯·알림 갱신이 끝나기 전에 다음 입력이 들어오면 같은 가드가 이를 거절할 수 있지만, 실기기에서 그 타이밍은 재현하지 못했다.

## 회귀와 수정

`judge_actions_are_disabled_while_write_updates_are_pending`은 시험 전용 중단점으로 후속 처리를 멈춰 두고 판정 버튼의 사용 불가 상태와 해제 후 복귀를 확인한다. 수정 전 동작을 재현하려고 `JudgeScreen`의 busy 전달값을 `false`로 고정한 비교에서 첫 버튼이 활성이라는 AssertionError로 실패했다. 원래 main에서 v2 시험이 실패한 현상 및 진단 로그와 같은 문제를 확인한 것이며, 원래 CI의 Looper 예외를 재현한 것은 아니다.

수정안은 기존 `busy`를 SCR-007에 전달해 판정·고르기·확인 작업을 끝날 때까지 비활성으로 보이게 한다. 시험은 v2 규칙으로 바꾸고 실제 사용 가능 상태를 기다린 뒤 누른다. `background_state_change_renders_dialog_on_main_thread`는 백그라운드의 상태 변경 뒤 시험 대화상자가 메인 Looper에서 만들어지는지 확인하지만, 기존 v1 시험 규칙에서도 통과했으므로 원래 Looper 예외를 수정 전 재현한 회귀 시험은 아니다. 개별 시험과 전체 CI의 결과는 PR에서 확인하며, 수정이 병합되기 전이라 상태는 open이다.

남은 것: 원래 CI의 간헐 예외를 통제된 조건에서 다시 재현한 증거와 실기기 확인은 없다. 이 변경과 기존 복원 실패·친구 배포의 판정은 별개다.

## 독립 리뷰 후 남은 확인

독립 Codex 리뷰 6097665599는 후속 작업이 끝나도 판정 칸의 비동기 재조회가 완료되기 전에 이전 버튼이 다시 활성화될 수 있고 재조회 실패 시 이전 칸이 오류보다 먼저 표시된다고 지적했다. 실험용 재조회 지연 시험에서 원래 코드의 이전 버튼이 활성으로 남아 실패했다. 저장 중 시각 선택 칸이 활성으로 남는다는 지적도 별도 지연 시험에서 실패로 확인했다. 이 두 시험과 수정 실험은 PR에 반영되지 않았으며 추가 확인과 처리가 필요하다. 기존 Looper 시험은 최초 구성이 false를 읽었는지 동기화하지 않는다는 지적도 남아 있다.
