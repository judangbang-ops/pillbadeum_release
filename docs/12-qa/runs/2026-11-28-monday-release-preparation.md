# 항목 248 · 월요일 APK 배포 결정 자료

## 현재 상태

오랑이 전달(사용자님 주말 위임, 2026-11-28): “안전 안내를 붙여 진행. 새 APK를 빌드·서명해 준비. 복원 검사는 매번 계속. 친구들에게 실제로 보내는 일은 월요일에 사용자님께 여쭘.” 공개 GitHub 릴리스는 Obtainium 업데이트 대상이므로 월요일 승인 전에는 만들지 않는다. 배포 중단 조건이나 미해결 복원 실패를 해결했다는 뜻은 아니다.

현재 main `98eb92be732bb39101d79886dae09e0e2899548b`의 versionCode는 커밋 수 **449**다. 이 문서 PR의 현재 변경 9커밋과 #84의 현재 변경 2커밋을 각각 기존 방식인 병합 커밋으로 main에 합치고 다른 커밋이 없다면 예상 versionCode는 **462**, versionName은 **0.1.0.462**다(449 + 문서 9 + 문서 병합 1 + #84 2 + #84 병합 1). 진행 중인 #84 리뷰 수정·추가 커밋이나 다른 병합 방식에 따라 달라지므로 실제 배포 커밋의 `git rev-list --count`로 다시 확인한다. 원본 서명 전 APK는 [릴리스 빌드 46118755596](https://github.com/judangbang-ops/pillbadeum_release/actions/runs/46118755596)의 `release-apk-unsigned` 산출물(2026-12-05 06:57:48 UTC 만료)이며, 압축 해제한 파일은 14,396,740바이트, SHA-256 `b880c9c04f7f56ebb88b0921890481e67947bf268ff1cf123957c43d4892a891`이다. **서명 전 파일이므로 설치·배포할 APK가 아니며 파일 해시는 서명된 APK의 해시가 아니다.**

앱 서명 키는 main만 허용하는 GitHub 환경 `personal-apk`에 있고 기존 [publish-apk.yml](../../../.github/workflows/publish-apk.yml)은 앱 키로 서명한 뒤 즉시 공개 GitHub 릴리스를 만든다. 이 워크플로를 실행하거나 기존 배포를 재실행하지 않았다. 새 앱 키 서명 APK가 없으므로 그 파일의 크기·SHA-256·인증서 지문과 1차 APK의 지문 일치를 아직 확인하지 못했다. `35:64:B6:82:4B:1E:3D:A0:74:7A:2E:97:96:6E:F5:5D:B9:CC:93:C5:E8:8A:7D:45:24:64:2F:E6:2A:32:95:36`은 워크플로에 설정된 **기대 지문**이며, 만들지 않은 APK의 측정값이 아니다.

오랑이 전달(사용자님 주말 위임)에 따라 서명만 미리 하는 별도 절차를 전제하지 않는다. 월요일 사용자님이 승인하기 전에는 #84를 병합하거나 공개 워크플로를 실행하지 않는다.

## 안내의 사실 확인

앱의 [설정 화면](../../../shared/src/commonMain/kotlin/com/judangbang/pillbadeum/ui/SettingsScreen.kt)은 `백업` 제목 아래 [화면 잠금과 Google 백업 설명](../../../shared/src/commonMain/kotlin/com/judangbang/pillbadeum/status/Labels.kt)만 표시하며 복용 기록을 파일로 내보내거나 가져오는 메뉴가 없다. 건강 카드 PDF·PNG 공유는 복용 기록을 복원할 수 있는 백업이 아니다. 설정 문구만으로 Google 백업이 실제로 완료됐거나 복원에 성공한다고 확인할 수도 없다.

## 월요일에 승인하면 할 일

1. #84의 독립 리뷰와 체크 결과, 배포할 커밋, 복원 검사와 미확정인 실기기 복원 위험을 사용자님께 보여 드리고, #84 병합과 자동 공개를 모두 포함하는 월요일 승인을 직접 받는다. 그 전에 최초 공개 노트에 지정된 안전 안내가 들어가고 링크된 설치 오류 안내에도 삭제 권고가 없는지 확인한다. 현재 자동 공개 노트에는 이 안내가 없으므로 해결되기 전에는 #84를 병합하지 않는다.
2. 승인 뒤 #84를 `main`에 병합하면 앱 경로 변경으로 릴리스 빌드와 복원 포함 에뮬레이터 검사가 돌고, 성공 등 워크플로 조건이 충족되면 앱 키 서명과 GitHub 공개 릴리스 생성이 이어진다. 공개 즉시 친구의 Obtainium이 업데이트를 받을 수 있는 대상이 되며, 각 폰에 보이는 시점은 확인 주기나 수동 새로고침에 따른다. 검사 실패나 키·버전 조건에 따라 공개가 건너뛰어질 수 있으므로 실행 결과를 끝까지 확인한다.
3. 승인 뒤 별도 서명·공개 워크플로를 실행하는 방법도 서명과 공개가 한 번에 진행된다. 수동 실행은 승인된 main 전체 SHA에 성공한 `push` 이벤트의 릴리스 빌드와 유효한 서명 전 APK 산출물이 있어야 하므로 먼저 그 실행과 산출물, 같은 SHA의 자동 공개 진행·완료 여부를 확인한다. 문서만 병합한 SHA는 빌드 경로 조건에 맞지 않아 기본 대상으로 삼으면 공개가 건너뛰어진다. 수동 실행은 복원 검사 성공을 스스로 요구하지 않으므로 정확한 커밋의 검사 결과를 별도로 확인하고 실패를 우회하지 않는다.
4. 공개 직후 릴리스의 APK 버전·코드·크기·SHA-256과 실제 서명 지문을 확인하고 1차 v0.1.0.297과 비교한다. 이는 공개 **후** 확인이며 실기기 Google 복원과 실서명 업데이트는 별도 확인이 필요하다.

#84 독립 Codex 리뷰 6097665599에서 판정 재조회 중 옛 버튼 활성화와 저장 중 시각 변경을 지적했고, 두 경우는 실험용 지연 시험에서 재현됐지만 코드에는 아직 반영되지 않았다. 이 상태를 사용자님께 알리고 처리 방침을 정하기 전에는 #84를 병합하지 않는다.

현재 `publish-apk.yml`의 자동 생성 노트에는 아래의 친구용 문구가 없다. 자동 공개 시 이 초안이 릴리스 노트로 저절로 들어가지는 않으므로, 승인·공개 전에 문구를 실제 공개 노트에 반영할 방법을 별도로 확인한다.
