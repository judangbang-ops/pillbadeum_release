# 항목 248 · 월요일 APK 배포 결정 자료

## 현재 상태

오랑이 전달(사용자님 주말 위임, 2026-11-28): “안전 안내를 붙여 진행. 새 APK를 빌드·서명해 준비. 복원 검사는 매번 계속. 친구들에게 실제로 보내는 일은 월요일에 사용자님께 여쭘.” 공개 GitHub 릴리스는 Obtainium 업데이트 대상이므로 월요일 승인 전에는 만들지 않는다. 배포 중단 조건이나 미해결 복원 실패를 해결했다는 뜻은 아니다.

현재 main `98eb92be732bb39101d79886dae09e0e2899548b`의 예상 versionCode는 커밋 수 **449**, versionName은 **0.1.0.449**다. 원본 서명 전 APK는 [릴리스 빌드 46118755596](https://github.com/judangbang-ops/pillbadeum_release/actions/runs/46118755596)의 `release-apk-unsigned` 산출물(2026-12-05 06:57:48 UTC 만료)이며, 압축 해제한 파일은 14,396,740바이트, SHA-256 `b880c9c04f7f56ebb88b0921890481e67947bf268ff1cf123957c43d4892a891`이다. **서명 전 파일이므로 설치·배포할 APK가 아니며 파일 해시는 서명된 APK의 해시가 아니다.**

앱 서명 키는 main만 허용하는 GitHub 환경 `personal-apk`에 있고 기존 [publish-apk.yml](../../../.github/workflows/publish-apk.yml)은 앱 키로 서명한 뒤 즉시 공개 GitHub 릴리스를 만든다. 이 워크플로를 실행하거나 기존 배포를 재실행하지 않았다. 새 앱 키 서명 APK가 없으므로 그 파일의 크기·SHA-256·인증서 지문과 1차 APK의 지문 일치를 아직 확인하지 못했다. `35:64:B6:82:4B:1E:3D:A0:74:7A:2E:97:96:6E:F5:5D:B9:CC:93:C5:E8:8A:7D:45:24:64:2F:E6:2A:32:95:36`은 워크플로에 설정된 **기대 지문**이며, 만들지 않은 APK의 측정값이 아니다.

친구에게 제공되지 않는 서명 APK를 준비하려면, 공개 릴리스 생성 단계를 실행하지 않는 별도의 main 전용 수동 서명 절차와 접근이 제한된 산출물 저장소가 필요하다. 동일 커밋의 원본·인증서·버전·권한·해시를 검증하고 서명 키를 로그와 산출물에 남기지 않아야 한다. 저장소가 공개이므로 산출물에 누가 접근할 수 있는지와 Obtainium이 감지하지 않는지 확인하기 전에는 비공개라고 단정하지 않는다. 절차를 추가해 main에 반영하는 변경은 문서만의 변경이 아니므로 여기서 병합하지 않았다.

## 안내의 사실 확인

요청된 문장 “앱을 지우거나 새 폰으로 옮기기 전에는 앱 안의 백업 내보내기를 먼저 하세요.”는 앱에 없는 기능을 지시하므로 친구에게 전달할 문구로 쓰지 않는다. [설정 화면](../../../shared/src/commonMain/kotlin/com/judangbang/pillbadeum/ui/SettingsScreen.kt)은 `백업` 제목 아래 [화면 잠금과 Google 백업 설명](../../../shared/src/commonMain/kotlin/com/judangbang/pillbadeum/status/Labels.kt)만 표시하며 복용 기록을 내보내거나 가져오는 메뉴가 없다. 건강 카드 PDF·PNG 공유는 복용 기록을 복원할 수 있는 백업이 아니다. 설정 화면의 문구만으로 Google 백업이 실제로 완료됐거나 복원에 성공한다고 확인할 수도 없다.

## 월요일에 승인하면 할 일

1. 먼저 서명 APK를 준비할 별도 절차의 안전성과 접근 범위, main에 적용할 권한을 확인하고 절차를 마련한다. 공개 릴리스·태그·테스터 배포는 이 단계에서 만들지 않는다.
2. 배포할 정확한 main 커밋과 이전 버전보다 큰 versionCode를 고정하고 복원 검사를 다시 실행해 결과를 확인한다. 간헐적 실패의 원인과 실기기 영향은 미확정이므로 통과가 안전성의 증명은 아니다.
3. 앱 서명 키로 서명한 APK의 패키지·버전·서명자 및 인증서 지문, 정렬·권한·크기·SHA-256을 검증하고 1차 APK와 지문을 비교한다. 실서명 덮어 설치를 별도로 확인할 수 없으면 미확인으로 남긴다.
4. 월요일 사용자님의 **친구 배포 승인**을 받은 경우에만 확정된 쉬운 릴리스 노트와 검증된 APK로 공개 태그·GitHub 릴리스를 만든다. Obtainium은 이를 확인해 친구들에게 업데이트를 제공하므로 공개 전 노트를 완성해야 한다.

기존 `publish-apk.yml`의 수동 실행은 에뮬레이터 성공을 스스로 요구하지 않고, 현재 자동 생성 노트에도 아래의 친구용 경고가 없다. 수동 실행만으로 확인을 대체하거나 공개 직후 노트를 고치는 방식은 위 순서에 맞지 않는다.
